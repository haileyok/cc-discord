| cc-bridge-multiplatform.AC3.3 | Missing or invalid BRIDGE_PLATFORM produces clear error message | unit | tests/test_cli.py (missing BRIDGE_PLATFORM exits with code 2 and error text; invalid value exits with code 2 and lists valid values) |

## Human Verification

| Criterion ID | Description | Why Not Automatable | Verification Approach |
|---|---|---|---|
| cc-bridge-multiplatform.AC2.1 | Full round-trip: Mattermost message -> zellij pane -> Claude response -> Mattermost thread | Requires live Mattermost server, zellij, and Claude Code process running together | Deploy cc-bridge with BRIDGE_PLATFORM=mattermost against a test Mattermost instance. Post a message in the configured channel. Verify: (1) task spawns in zellij, (2) Claude response streams back to the Mattermost thread, (3) thread structure is correct (root post + replies). |
| cc-bridge-multiplatform.AC2.4 | Text commands work end-to-end in live Mattermost | Unit tests verify parsing and dispatch but not actual Mattermost message flow | In the test Mattermost instance, type each `!command` and verify the bot responds correctly in-thread. Confirm `!start` spawns a task, `!stop` stops it, `!list` shows active tasks, etc. |
| cc-bridge-multiplatform.AC2.5 | Slash commands work with real Mattermost webhook configuration | Requires Mattermost admin to create slash commands pointing to bridge URLs | Configure slash commands in Mattermost admin panel pointing to `http://<bridge>:8787/v1/mattermost/slash/<cmd>`. Invoke each slash command and verify responses appear correctly (ephemeral for errors, in-channel for success). |
| cc-bridge-multiplatform.AC4.1 | Package installs as `cc-bridge` CLI command via `uv tool install` | Requires actual package installation in a clean environment | Run `uv tool install .` in the repo. Verify `cc-bridge --help` works from a fresh shell. Verify `cc-bridge serve`, `cc-bridge init --platform discord`, `cc-bridge doctor` all resolve correctly. |
| cc-bridge-multiplatform.AC5.2 | Discord bot connects, receives messages, streams responses, handles approvals — identical to pre-refactor | Requires live Discord bot token, server, and channel | Deploy cc-bridge with BRIDGE_PLATFORM=discord against the existing Discord setup. Run through the standard workflow: (1) /start a task, (2) verify transcript streaming, (3) trigger an approval prompt and approve/deny via emoji, (4) /stop the task. Compare behaviour to pre-refactor baseline. |
| cc-bridge-multiplatform.AC5.3 | Slash commands sync with Discord and function in live guild | Unit tests cover the wrapper logic but not Discord gateway sync | After deploying with BRIDGE_PLATFORM=discord, verify slash commands appear in the Discord command picker and execute correctly. Test at least /start, /stop, /list. |
| cc-bridge-multiplatform.F1 | WebSocket disconnects mid-task: output resumes after reconnection | Requires simulating network disruption against live Mattermost | While a task is running against Mattermost, kill the network connection (e.g., `iptables -A OUTPUT -p tcp --dport 443 -j DROP` then restore). Verify: (1) task continues in zellij, (2) bridge reconnects within backoff window, (3) queued output posts to thread after reconnection. |
